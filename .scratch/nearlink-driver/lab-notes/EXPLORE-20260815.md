## kernel 态主动实验 #1 — H2D_MSG_SLE_OPEN(=29) 控制传输

实验: `bmRequestType 0x21, bRequest 0x00(HOST_TO_DEV_SEND_MSG), payload 4B LE 1D 00 00 00` → 1-4

- INT EP 出现 `LIBUSB_ERROR_IO`（设备 teardown 时有活动）→ 然后 NO_DEVICE

- **协议方向正确**（设备接受控制消息并有反应），但 **SLE_OPEN 序列不完整**

- 固件下载可重复执行（1-4 已重灌回 kernel 态 2 次）—— 开发调试不怕搞挂设备
- usbmon 无法开启（debugfs 权限受限，xanmod 内核）→ 无法抓 USB 层流量

待验证: 子代理 C 的完整初始化序列（NV 推送格式 + 消息通道 framing + ack 格式）

## kernel 态初始化序列 (SDK 源码证实, sle_host_register.c:145-165 + customize_bsle.c:682)

完整顺序:
1. `hbsle_hcc_customize_h2d_data_cfg()` → `hbsle_hcc_custom_ini_data_buf()`:
   bulk 数据通道(HCC_CHANNEL_AP) 发 `[hcc头] [bsle_msg_tag{type=0 CUSTOMIZE_DATA, len}] [bfgn_bt_customization_stru]`
   - bsle_msg_tag = uint16 type + uint16 len (4B LE)
   - BSLE_MSG_HCC_TYPE_CUSTOMIZE_DATA = 0 (enum 首值)
   - 总 ≤ BSLE_LARGE_NETBUF_SIZE = 800B
2. 等设备状态: `hbsle_hcc_customize_get_device_status(BSLE_STATUS_CUSTOMIZE_RECEIVED)` (C2H 消息)
3. `hcc_send_message(HCC_CHANNEL_AP, H2D_MSG_SLE_OPEN=29, ...)` → USB 控制传输 0x21/0x00 + 4B LE
4. 等 `BSLE_STATUS_BOOT_FINISH`

→ 我们只做了 3（SLE_OPEN 控制传输），缺 1/2/4 → 设备无配置 → 重启回 boot。

## 双设备 kernel 态的第 2 个限制: libusb 预灌跳过 PM 上电

实验: libusb 预灌双设备 → 挂驱动（双 kernel 态 ✅）→ open /dev/hwsle
结果: `sle send open btc msg fail ret 0x7851`（hcc_send_message 失败，dmesg 无
pm_svc_open 序列）

根因推断: 驱动触发的固件下载路径会走 `pm_svc_power_on`（hcc 服务完整初始化 + PM 上电），
libusb 预灌绕过了它 → 设备虽 kernel 态但 hcc 服务/PM 状态未就绪 → SLE_OPEN 消息发不出去。

对比（票 08 成功时 dmesg 序列）:
  firmware_download_etc::succ → pm_svc_open::first svc open, pm_svc_power_on succ
  → pm_sle_open success → sle device open success

结论: 要让 kernel 态 dongle 的 SLE 通道可用，需要完整走驱动触发的固件下载路径
（或 hack pm 初始化）。hwsle-probe.sh 实测需先走驱动下载路径（单设备）。

工具备注: hwsle-probe.sh 在 libusb 预灌的 kernel 态设备上 open 失败（EINVAL ← 0x7851），

## 🎉 SLE HCI 方言打通 (2026-08-16 重大突破)

**HCC STATE_EXCEPTION 根因**: 时序竞态——BSP_READY (INT EP 通知) 在 hcc module init 完成前到达，
`pm_bsp_init_ready` 里的 `hcc_switch_status(HCC_ON)` 因 handler NULL 静默失败 → hcc_state 卡 FORBID。
重载驱动 (rmmod ×2 → insmod) 后时序正常 → 数据通道就绪。

**SLE HCI 命令验证 (14 命令全响应!)**:
- 方言 = **DLI 风格** (OpenHarmony 栈 opcode): HCI_RESET/DLI_RESET (0x0408) 回 status=01;
  **DLI_READ_LOCAL_VERSION (0x0404) 回完整数据**: version=0x6c(108), manufacturer=0xa1(161), hw=0x00
- 事件格式: `a2 [02 00 04/len] [00 01/06 status] [opcode 2B 回显] [status] [数据]`
- 大部分 opcode 回 status=0x06 (pending/unsupported — 需正确参数)
- DLI_SET_ADV_ENABLE 无响应 (需先 SET_ADV_PARAMS 成功)

**意义**: 星闪宝子的 HCI 命令面完全可达! 可继续: 正确参数广播/扫描/连接 → SSAP 服务。
